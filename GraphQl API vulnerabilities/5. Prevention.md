# Preventing GraphQL attacks

1. Disable Introspection, if it isnt ment to be used by the general public.
    - Reduces unwanted information disclosure and how the API works.

2. If it's a public API service, you should review the API's schema to make sure that it doesn't expose unintentneded fields to the public.

3. Disable Suggestions, It prevents attackers from using CLairvoyance to goad/glean information about the underlying schema.
    - In Apollo Server v4, you can fisable siggestions using..
    ```code
    hideSchemaDetailsFromClientErrors
    ```
4. Make sure the API's schema does not expose **any private user fields** Eg: email addresses or userIDs.

---

## Preventing Brute force attacks specifically..

The general defense against this invloves restricting the complexity of queries accepted by the API, and reducing the opportunity for attackers to execute dental of service (DoS) attacks.

1. Limit the query depth of your ApI's queries.
    - This refers to the number of levels of nesting within a query.
    - Heavy nested queries are often inefficient anyway and can be used to make a DoS attack.

2. Configure operation limits.
    - operation limits enables you to configure maximum number of unique fields, aliases, and root fields that your API can accept.

3. Configure the maximum amount of bytes a query can contain.

4. Consider implementing cost analysis on your API.
    - This is where a library application identifies the resource cost associated with running a query when recieved.
        - If the query is too resource intensive/complex it drops it.

## Preventing CSRF over graphQl specifically..

1. Make sure that your API only accepts queries over **JSON**encoded **POST**

2. Make sure that your API **Validates** that **content provided** **matches** the **supplied content type**

3. Make sure that your API has secure CSRF token mechanism.
