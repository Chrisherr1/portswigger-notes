# What are AI-powered web application security scanners ?

Ai-powered scanners are testing tools that combine traditional crawling and request generation with LLM-driven reasoning.

> Like Dynamic Application Security Testing Scanners... They can..

1. Authenticate as users
2. Crawl applications
3. Send HTTP requests
4. Chain multiple actions

## Traditional vs. AI-powered scanners

The difference is how decisions are made..

**Traditional** - rigid,instruction-based. They lack semantic understanding, they cannot read a page to determine its purpose.

> Instead they rely on pattern matching and known vulnerability signitures.

***AI-powered scanners** - Autonomous reasoning.
They can interpret web content and plan their next actions.

    AI-powered scanners features:
        1. Using LLM reasoning to decide what to test next.

        2.Interpreting application responses semantically.
            - They read the text in the response to understand its context enabling them to identify complex business logic that a tradition scanner might ignore.

        3.Selecting tools and constructing requests based on model output.
            - Some AI scanners use "Tools" to interact with APIs,databases, or UI elementes based on their own internal reasoning.

        
## Ai-powered scanner vulnerabilities

Most AI-powered scanner vulnerabilities arise when attacker-controlled content influences the scanner's reasoning and tool usage.

This occurs because these scanners treat the text they analyze as a source of information to plan their next move. If the AI model cannot reliably distinguish between application data and instructions, then untrusted content can alter scanner behavior.

> This is very specific.. It's like the injection must be put in before the tool gets used to check it.

## Indirect prompt injection in AI-powered scanners

Indirect prompt injection is a significant risk with AI agents.

> This occurs when an attacker embeds malicious instructions in stored content, which the scanner then treats as part of its action plan.

Sequence:

1.Malicious instructions are embedded in stored content, for example, within comments or blog posts.

2.The scanner reads this content during its crawl process.

3.The LLM interprets the injected text as actionable instructions rather than passive data.

4.The scanner executes tool calls or generates requests based on the injected text.

> Some consequences of this..

1. Performing unintended state-changing actions
    -For example, the scanner might delete users or modify account settings.

2. Accessing sensitive data
    -The scanner may be instructed to access database records or configuration files.

3. Making unauthorized internal requests.
    -The scanner may interact with internal APIs that are not exposed to the public internet.

These vulnerabilities can have severe consequences because scanners often run inside internal networks,operate with authenticated sessions, and have access to APIs or services unavailable to external users.

> Conceptually, This resembles CSRF.

In both cases, the attacker cannot directly preform the protected action themselves.

Instead they trick a more privileged actor into doing it on their behalf.

## Crafting effective injection prompts

Common techniques:

1. Adopting a persona, try to make yourself seem like someone who'd have privilege.

2.Social Engineering, try and give it information only a person with access would know.

3. Urgency and consequence, implying that the instruction is required to prevent harm or data loss can reinforce compliance.

> If there are multiple injections on the same page, it might confuse the model and reduce the effectiveness.(Spread injections over different locations).
